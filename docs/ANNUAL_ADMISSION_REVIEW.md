# 年度公開時の確認と引き継ぎ

最終更新：2026年10月11日。対象：岡山子育てナビ。

## 自動取得と制度本文の確認を分ける

既存の日次更新は、月次・4月の受入見込みと年度途中の締切、公表状況を更新する。HTMLの記事、点数の規則、必要書類、制度条件まで自動照合したものではない。新年度のガイド公開後は、下記を人が確認する。公開前の未確定情報を推測で埋めない。

2027年4月入園の令和9年度ガイドは、監査時点では2026年10月14日公開予定。これは本書作成時に確認した予定で、将来の公開状態を保証するものではない。公開当日の確認担当は運営者またはその依頼を受けた編集担当とする。

## 完了条件と記録

1. 新ガイドが実際に公開されたことを確認し、年度・公式URL・確認日を記録する。
2. 上表の全対象について「変更あり／変更なし／未確認」を記録する。変更なしの場合も照合済みの根拠を残す。
3. 変更した本文・計算規則の差分を確認し、必要なテストを実行する。
4. JSON取得成功だけを理由に、制度本文を「新年度更新済み」としない。
5. 未確認ページは対象年度と未確認事項を表示し、全対象の照合が終わるまで全体完了にしない。
6. 反映コミットとPagesの公開成功を確認し、主要ページの表示を確認する。

記録例：`対象ファイル／年度／原典URL・節／確認日／変更あり・なし・未確認／実施者／変更概要／確認結果／コミット`。

## 月次と4月の回帰確認

P01の表示変更時にも、新年度ガイド公開時にも確認する。

- 4月資料未公表：月次を表示し、4月切替UIを出さない。
- 対象年度の4月資料が有効：トップと施設MAPの初期表示を4月に切り替える。
- `hoikuen.html?availability=monthly`：4月資料が存在しても月次を表示する。途中入園からのリンクもこの指定を維持。
- 月次PDFの公表終了：取得済みの旧資料は参考として保持し、受付終了と次月未公表を明示する。
- 月次取得・読込み失敗：未公表とは区別して失敗と最終確認を表示する。4月資料を消さず、月次欄に4月の値を混ぜない。
- 次月PDF公表：公表済みと園別データへの反映済みを区別し、取得できた対象月へ切り替える。
- 締切の17:15をまたぐ：確認済みの次の締切へ移る。年度途中には4月募集を混ぜない。
- 古い年度の4月データ：既存の有効年度判定により初期表示の対象から外れる。

実行：`node tests/test_admission_ui.cjs`、`python3 -m unittest discover -s tests -p 'test_*.py'`。テストデータでの検証と、新資料公開後の実表示確認は分けて記録する。

## コンテンツの継続方針

- 既存3カテゴリを維持し、カテゴリ・タグをむやみに増やさない。少ない本数を埋めるための記事は作らない。
- 園種別3記事と見学3記事は固有の問いを維持する。トップは全体導線、入門記事は家庭の初動整理、保活記事は地域の受入状況の考え方を扱う。
- 備忘録の13記事と、別導線の入園準備ガイドを混同して集計しない。ガイドは備忘録の「入園準備・通園生活」の読む順からも案内する。
- 体験の期間、洗浄回数、失敗、園名、子の年齢等は、本人の確認なしで作らない。D110Mの使用機種は2026年10月11日に本人確認済み。耐久・洗浄テスト等は確認していない。
- 商品仕様、本人経験、一般的な助言を分け、メーカー資料への到達を確認する。購入不要の判断も読者に伝える。
- 広告scriptだけで違反と判定しない。広告実表示・自動広告設定・地域条件・解析通信は別途確認する。運営者・プライバシー等の説明ページを一律に広告禁止と扱わない。
